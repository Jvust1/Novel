# PDF 参考读取依赖安全修复

本轮只把已有 `pypdf>=4,<6` 更新为官方稳定版 `pypdf==6.19.0`，保留现有 `PdfReader` / `extract_text` 接口、可选阅读器顺序及全部写作、保存和确认协议。不复制 PDF 解析器，也不为静态计数关闭规则。

## 为什么要更新

旧依赖范围实际安装 5.9.0，并排除了已修复版本。上游已公布字体 `/Widths`、`/ToUnicode` 及 XForm 文本提取的资源消耗风险；其中 [字体宽度公告](https://github.com/py-pdf/pypdf/security/advisories/GHSA-g9cg-prrw-2r8q) 标明 `<6.18.1` 受影响。Novel 的 PDF 参考入口真实调用 `page.extract_text()`，因此这不是未使用依赖的告警。

本地原创 650 字节 PDF 使用稀疏宽度数组和极大的声明字符范围。经实际 `extract_reference` 入口，5.9.0 在受限子进程触发 CPU 限额退出；6.19.0 返回完整预期文本。这个相关资源消耗反例独立编写，没有使用私人 PDF 或下载攻击样本，也不把它说成覆盖了全部公告。

## 使用方式与边界

- GPT + GitHub 插件的对话写作仍无需作者安装 Python；依赖升级适用于确实运行本地工作台的执行器
- 已运行旧工作台的执行器需按更新后的 requirements 安装依赖；仅下载源码不代表其已有环境已升级。不要用旧 5.9.0 环境读取来源不明的 PDF
- 正常多页、压缩内容流及空白页继续走原读取接口；损坏或加密且无法读取的 PDF 会失败，不发送模型请求、不改已保存文风
- 原有损坏/加密 PDF 在工作台中可能呈现异常信息，而不是普通错误提示；此行为没有在本轮改写，不应把失败说成已提取成功
- 资源限额用于**回归测试子进程**：内存上限、CPU 上限及墙钟超时同时存在。应用读取器本身并未新增通用沙箱或所有输入资源配额
- 不保证所有恶意 PDF、可选 Docling/MarkItDown、远程文件或整套依赖不存在风险；pip check 验证依赖一致性，不等于漏洞扫描

版本、源码提交、完整许可及公开公告见 [上游记录](../third_party/pypdf-reader-security/NOTICE.md)。完整本地、精确远端 CI 和 ZIP 解出结果以 [候选记录](../governance/pdf_reader_security_candidate.json) 及对应 Draft PR 为准；旧 #67 包及验证记录保留，不回写其历史结果。
