# 工作台人物来源核对与明确重新载入

这次修复来自原创离线界面反例：另一会话更新已保存人物的说话方式后，旧会话仍用旧人物卡生成正文并保存本地候选；在模型响应期间更新人物，旧结果也能继续保存。正式已接受档案入口已有来源检查，同类反例在那里正确停止。本次没有发现或宣称作者接受记录被绕过。

## 现有工作台里的操作

- 加载项目时保留人物来源指纹。当前会话新增的未保存人物仍可用于生成，只要其已保存来源没有被其他会话改动
- 已保存人物变化时，界面展示当前会话与磁盘人物两版。当前会话人物、手工计划、章目标和备注都保留，不自动覆盖，也不自动把旧人物写回
- 可以先下载当前会话人物 JSON 草案。核对两版后，明确勾选同意替换，再点击“重新载入当前已保存人物”。这一步会替换当前会话人物；未保存的新增人物应先下载留存。勾选绑定两版内容和当前项目，另一会话再次更新时旧勾选不适用
- 重新载入保留待写计划及其他编辑，但不让旧人物背景下的计划自动恢复有效。重新生成场景计划，或重新载入所选大纲章节并核对计划后，再明确点击按计划写正文
- 同一会话修改人物后，已有绑定计划也需要重新生成或载入。一步生成会按当前人物重新规划，不把旧计划当作新确认
- “保存人物到本地”和“应用锁定”先比较原来加载的人物来源，再沿用项目锁和原子文件写入。冲突或写入失败时，不改变会话人物及锁定状态，也不覆盖另一会话的新卡片
- 已确认记忆提交后的正常人物读回更新同一来源绑定。若有新的未保存人物编辑，继续保留；手动重新载入仍须核对并明确同意替换

## 使用同一套已有门禁

复用 ProjectStore 的项目锁、单文件原子写入、JSON 读取，及 provider 的 request_guard。人物卡使用完整 JSON 内容指纹，未知作者扩展字段也参与比较并在保存时保留；文件不存在与已经保存的空列表分别绑定。没有新增接受状态、人物版本库或另一个多文件事务协议。

生成计划、正文、审校、局部修订和复审时，在每次实际 HTTP 发送前和响应体读取后核对本次固定的人物来源；格式回退也重新检查。请求期间来源或本会话人物编辑变化时停止后续请求。最终计划或正文发布前再次核对，正文保存仍在原项目锁内。切换项目后返回旧草案，不把新磁盘来源悄悄配给旧会话人物。

刷新只是读取和明确替换会话人物，不等于接受计划、正文或记忆；正文和记忆仍需各自明确确认。保存本地候选也不等于正式已接受档案推进。原预算、接受历史、记忆恢复、Style Lab、参考编码和 PDF 修复继续保留。

## 验证与范围

独立原创反例覆盖旧会话保存/锁定、写入失败、未保存新增人物、跨项目缓存恢复、明确重新载入和旧确认失效。实际离线 HTTP 流程覆盖各阶段及最终保存前变更；原有完整测试与双 Python 矩阵继续执行。精确结果见[候选记录](../governance/character_source_candidate.json)和 Draft PR 的对应提交 CI。

本轮不增加依赖或复制上游源码，已有许可证及来源 pin 保留。云浏览器连接故障，外部 AI 预审未完成；工程测试不替代外部审计。此保护面向合作的本地项目会话，不是恶意目录竞态沙箱或 Drive 保存协议。题材、故事设定等其他文件保持原有各自边界，不能据此宣称所有来源都有相同检查。普通 GPT + GitHub 插件入口继续读取作者指定的私有档案，不要求运行本地工作台。
