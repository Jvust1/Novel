# Novel Product Spec v0.2

## 0. Reference Pack：参考小说输入

支持用户给出多本参考小说或章节样本（TXT / DOCX / PDF；后续扩展 EPUB）。

每个来源只用于提取派生特征，不直接进入生成正文提示词长上下文。

系统为每个来源建立：
- source_id / hash / 权重
- 题材与受众
- Style DNA
- Story DNA
- 可选人工备注
- 非可逆 shingle signature
- 相似性风险阈值

## 1. Style Lab：文笔与叙事风格学习

至少提取：
- 句长均值、方差与局部波动
- 段落长度分布
- 对白占比与对白轮次长度
- 叙述 / 动作 / 心理 / 环境比例
- POV 与叙事距离
- 信息密度与解释倾向
- 词汇层级、口语度、书面度
- 标点节奏
- 修辞与意象密度
- 情绪表达：直述 / 行为 / 生理 / 留白
- 章首/章末节奏
- 角色 idiolect（说话习惯、句式、回避方式、称呼体系）

多来源按权重融合为项目 Style DNA，并允许用户手动锁定或覆盖维度。

## 2. Story Lab：剧情套路学习

学习的是**抽象模式**，不是具体事件复制。

至少提取：
- 开篇切入方式
- 主角初始缺口与核心承诺
- 冲突类型与升级路径
- 爽点/回报/反转间隔
- 信息释放节奏
- 悬念和伏笔生命周期
- 角色关系推进模式
- 单章场景结构
- 章末钩子类型
- 小高潮 / 大高潮 / 卷末兑现结构
- 新地图 / 新关系 / 新能力的引入频率
- “压制 → 选择 → 代价 → 回报”循环
- 读者期待建立与兑现方式

多个参考来源形成 Story DNA。若生成方案与某一本参考书在角色、设定或事件序列上过度相似，必须重构。

## 3. Market Lab：番茄/目标平台适配

项目保存可更新的 Market Profile：
- 平台
- 男频/女频/目标受众
- 题材与标签
- 书名策略
- 简介结构
- 开篇前三章节奏
- 单章目标长度
- 更新节奏
- 当前公开平台规则摘要
- 用户导入的后台指标

Market Lab 输出的是建议和约束，不覆盖 Story Bible 的原创性与因果要求。

## 4. Story Forge：原创故事生成

从 Style DNA + Story DNA + Market DNA 生成多个原创候选：

- 核心卖点
- 一句话故事
- 主角欲望 / 缺陷 / 反差
- 核心冲突
- 世界规则
- 情绪价值
- 长线升级路线
- 主要人物关系网
- 前 3 章承诺
- 前 20 章看点分布
- 卷级结构

每个候选都运行参考相似性与“换皮风险”检查。

## 5. 故事项目

项目至少保存：
- 书名候选、题材、受众、基调
- Story Bible
- 总纲 / 卷纲 / 章纲
- 世界规则
- 不可违背事实
- 开放伏笔
- 已兑现承诺
- 读者当前应知道/不知道的信息
- 目标字数和完结条件

## 6. 人物系统

每个角色至少包含：
- 身份与外在特征
- 核心欲望 / 当前目标
- 恐惧 / 缺陷 / 自我欺骗
- 秘密
- 关系状态
- 说话习惯与语言层级
- 已知事实 / 未知事实 / 错误认知
- 当前资源、能力、伤病和位置
- 最近关键变化
- 长期弧线
- 不可随意改变的角色核
- locked 状态

## 7. 大纲与场景规划

四级规划：
1. 全书 promise / ending target
2. 卷 / arc
3. 章节
4. scene

每个 scene 至少包含：
- POV
- 谁想要什么
- 阻力
- 信息释放
- 人物选择
- 代价
- 状态变化
- 伏笔推进/回收
- 情绪与关系变化
- 本场景存在的必要性
- 转入下一场景的因果

用户可编辑确认后再写正文。

## 8. 章节生成模式

- **快速草稿**：计划 → 正文
- **标准**：计划 → 正文 → 连续性审校 → 人味审校
- **精修**：计划 → 正文 → 连续性 / 人物 / 文风 / 原创性多审校 → 局部修订 → 再审

精修模式优先局部修复，不默认整章重写。

## 9. Human-feel Engine：降低模板感

检测：
- 句长/段长过度均匀
- 模板连接词和弱化词高密度
- 高频总结式修辞
- 动作后重复解释情绪
- 角色同声
- 对白过度完整、理性、会总结
- 无功能环境描写
- 心理重复解释
- 段尾频繁升华
- 场景缺少独特物理细节
- 事件转折仅靠作者安排
- 连续多章使用同一种冲突模板
- 章末机械断句式钩子
- 修复后语言被统一“抛光”得过于整齐

增强：
- 角色 idiolect 约束
- 局部节奏波动
- 动作/对白/内心的非对称分配
- 省略与留白
- 由人物关系产生的信息遮掩
- 具体而不通用的场景细节
- 长期习惯与历史痕迹回收

禁止通过错别字、乱码、异常标点等方式伪装成人类文本。

## 10. 连续性与长期记忆

继续采用：
- Canon
- Active
- Recall

至少追踪：
- 时间、位置、物品、能力、伤病
- 人物知道 / 不知道 / 错误相信什么
- 关系变化
- 伏笔 active / resolved
- 世界规则
- 因果链
- 章节承诺与兑现
- 人物长期行为习惯

## 11. Originality Gate：原创性检查

生成前后都检查：
- 参考文本 shingle overlap
- 长片段语义近似
- 人物组合相似度
- 世界设定相似度
- 关键事件序列相似度
- 标志性表达复用
- 单一参考来源影响是否过重

高风险时重做 premise / outline / scene，不以同义改写解决。

## 12. Commercial Readiness Gate：发布前检查

每章发布前输出：
- 本章核心看点
- 因果链是否成立
- 人物是否有真实选择
- 新信息/回报是否足够
- 章末拉力
- AI 味 / 模板感风险
- 连续性风险
- 参考相似风险
- 敏感/违规内容人工检查提示
- 是否建议发布 / 需要局部修改

## 13. Release Pack

为目标平台生成：
- 书名候选
- 简介候选
- 标签/题材建议
- 封面视觉 brief / 生图提示
- 正文章节
- 章节标题
- 发布前检查报告
- 后续 3–10 章剧情缓冲区

不默认自动上传平台；先保证作者可审阅、可编辑。

## 14. Platform Feedback Loop

允许用户导入番茄作者后台真实数据后，系统分析：
- 开篇表现
- 读完/留存类指标
- 追更与互动
- 章节波动
- 哪个剧情节点后出现显著变化

只调整**未来**剧情和节奏，不反向篡改已发布事实。

## 15. UX 原则

- AI 先给结构化建议，用户确认/编辑后再写。
- 用户可锁定人物、事实、段落、伏笔和卷级方向。
- 所有“优化”必须说明改了什么、为什么。
- API Key 只存在会话或本地环境变量。
- 原始参考小说、手稿和大产物默认留在本地/Drive，不进入 GitHub。
- 系统不得宣称“100%绕过 AI 检测”或“保证爆火”；使用人工盲评、原创性和真实平台数据证明质量。
