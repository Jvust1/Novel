# 场景演绎升级：story-craft 1.1

日期：2026-10-14。承接 PR #93，基础提交 `b9249d791fa09519ea2c40cd7d8b481e1249a4b9`。这是候选变更说明，不是合并回执；当前 main 与 CI 以实际 GitHub 记录为准。

## 从源码发现的缺口

原共享流水线给初审和复审的 extra_context 只有历史与反复用提示，没有本轮 user_notes 或 Style DNA；修订拿到正文、问题和风格，却没有本次计划、设定和人物资料。起草时要求保留的语气可能因此在审改阶段失去依据；计划中本来有的应答与选择也不便有根据地恢复。这是源码层面的缺口，不等于已读过作者真实小说并确认了其平淡原因。

## 实际改动

1. `story_craft.py` 升为 1.1：计划指出焦点场面；正文用人物目标组织注意力、判断、潜台词与混合感受；声线来自已有 speech 和关系，不靠口癖；关键应答展开，过渡压缩，不平均分配篇幅。审校用有依据的三个表达类别定位问题，仍最多五项且保留重规划路径。
2. `story_craft_profiles.py` 提供九类、三阶段的阅读回报提示，实际接入规划/起草/审校工厂。只按明确标签选择最多两个类型，不改 genre 存档；未知或模糊配置不自动选卡。只把库内静态文字放入 system 消息，作者原始文本留在 user 消息。类型卡不是质量评分、作者偏好推断或反转配额。
3. `editorial_context.py` 无 I/O 地构建本轮依据，`NovelEngine.run_from_plan()` 真正传递给编辑调用：初审/复审有本轮要求、风格与软篇幅；修订有计划、设定、人物声线/知识边界与本轮要求。省略额外人物副本的 secret 原字段；不是全域秘密过滤器，已有历史和其他字段仍受事实/揭示限制。
4. user_notes 摘要加入原最终报告的输入指纹并受既有绑定保护。结构问题照旧暂停自动修订；原 repair/review 方法签名不变，独立 reviewer 也适用。直接旧式 repair 不伪造计划，不把上下文当作作者接受。
5. 对话提示包 README 显式连接 [04 阶段补充](prompts/natural-fiction/04-scene-execution.md)，不增加自动模型轮次，不覆盖真实章节。
