# 故事写作能力升级：story-craft 1.0

日期：2026-10-14。基于 `main@6afdd3681824ddf17f9e598b7ef7de4389b405f5` 的候选变更；是否合并、生效及 CI 结果以实际 GitHub ref/回执为准，不用本文代替合并记录。

## 为什么改

旧 `novel_ai/prompts.py` 已有目标、阻力、选择、代价和状态变化字段，并非完全没有情节规划。此次检查发现的可改进点是：字段要求较抽象；缺少对手如何回应、后果如何传递、本章如何兑现的具体约束；未设置 Style DNA 时统一回落到“克制”；审校与修订主要强调局部处理，缺少显式的结构问题回到策划路径。

这些是对源码和提示的诊断，不是对作者实际小说的逐章审读。本次没有读取私有正文，不能据此断言某本书的平淡原因已被实证确认。

## 变更

- 新增 [00 故事设计](prompts/natural-fiction/00-story-design.md)：阅读价值、人物私人得失、对手回应、有代价的选择、跨场后果、张弛、回报与余韵。事实保护不等于禁止授权范围内创作；既有事实仍锁定。
- `01 / 02 / 03` 与提示包入口连通：关键场面展开、故事优先审校、表达修复与结构改计划分流。低外部冲突、温暖、幽默与完整结局不自动判作缺陷。
- 程序的四个提示工厂显式接入 `novel_ai/story_craft.py`，保持函数签名、两个消息的返回形式和原有 JSON 字段。无 Style DNA 时尊重本书 genre/tone，不强制统一克制口吻。
- 审校用既有 `category` 字段标记 `story_structure_requires_replan`，要求给出定位、依据和最小变更方向；修订提示不得执行未确认的结构改动。这是提示级协议，不是新增确定性故事质量检测器或自动改纲执行器。

没有修改 `models.py`、模型 provider、引擎调用次数、存档 Schema、已接受历史或作者确认逻辑。提示文本有所增加，实际输入 token/费用仍由使用的 provider 与计费决定；不能宣称零 token 成本。记忆抽取和参考文风分析不注入故事创作规则，避免让记录员编剧情。

## 质量验收方法

[六个合成用例](../benchmarks/story_craft/cases.json) 覆盖安静日常、关系边界、公平悬疑、能力/资源代价、完整结尾及“退回计划而非加料”。它们是测试条件，不是通过的生成样本；当前 `evaluation_status = not_run`。未引用私有小说、参考书原文或真实创作进度。

实际验收时，对旧提示与新提示使用相同作品资料、模型及参数、篇幅目标与工具权限；记录准确 ref 和资料版本，每种条件做多次生成以观察随机差异。不要用不同模型或更长篇幅冒充提示提升。给读者隐藏版本来源、随机顺序，比较是否更在乎人物、选择是否可信、关键场面是否可感、节奏和回报是否满足、是否愿意续读，并保留“无明显差异/旧版更好”的选项与原文依据。同步记录事实、知识和揭示越界；出现越界不得以更刺激抵消。没有读者评审时如实记为自审，不冒充盲评。

## 使用与回退

对话入口沿 `docs/GPT_WRITING_ENTRY.md` 实际读取提示包 README，然后在计划前读取 00；已打开的旧会话需重新读取，GitHub 文件变更不等于会话自动热更新。程序入口在运行本次提交后由原提示工厂加载规则，无新增服务和依赖。

已确认的旧章不会自动重写；结构改动需新计划确认、正文复审与作者接受，真实作品仍默认只保存到作者指定的私有存储。回退本次提交即可移除新规则，不需要迁移存档。工程记录见 [story_craft_upgrade.json](../governance/story_craft_upgrade.json)。
