# 故事升级续篇：停止无效润色，让场景真的发生

日期：2026-10-14。承接 [story-craft 1.0](STORY_CRAFT_UPGRADE.md)，基于 `58bfe0b52ee8ad64c87f4aeabfb73bd476bfa7e9` 继续完善 PR #93。是否已合并、当前 CI 是否完成，仍以实际 GitHub 记录为准；这里不是合并回执。

## 1. 这次补上的运行时缺口

1.0 已要求审校把结构缺口标为 `story_structure_requires_replan`，但原 `NovelEngine.run_from_plan()` 仍会对所有 revise 结果调用自动修订。提示说“退回计划”不能代替程序分流。

新增 `novel_ai/story_revision.py`，由共享引擎在合并模型审校、确定性诊断和外部审校后执行：

| 当前审校 | 后续路径 |
| --- | --- |
| 有明确的结构重规划分类 | 原稿保留为候选，不发自动修订请求；状态 `awaiting_plan_revision`，先修订场景计划并取得作者确认 |
| 只有普通 revise 问题 | 维持既有的最多一次自动修订，并对最终正文重新审校 |
| pass 且没有结构分类 | 交作者审阅，不等于已接受 |
| 没有运行审校 | 明确 `review_not_run`，不能宣称通过 |

结构分类即使被模型误标成 low 或顶层 pass，也不能进入自动润色；保留问题证据，只把最终审校结论纠正为 revise。混合了结构和表达问题时，整次自动修订暂停：现有接口返回完整正文，没有可靠的段落权限隔离，不能假装只修独立小问题。作者之后可以明确授权局部范围，但本次没有新增自动范围执行器。

直接调用 `NovelEngine.repair()` 遇到结构问题时，在请求模型前抛出 `StoryReplanRequired`（ValueError 子类）；调用方应显示“需重规划”，不能把异常当成已修订稿。共享流水线在进入 repair 前分流，因此不会丢弃已经生成的原稿；单写手、独立审稿引擎以及共享该流水线的路由调用都适用。

每次最终分析报告增加 `story_revision_route`，包含处理状态、下一步和对应问题的零基索引，受既有全文/计划/报告绑定保护。不新增计划或审校必填字段，不迁移小说存档，不代替作者确认，也不自动修改正式记忆。未识别的分类仍按原 pass/revise 路径处理；这只是对**已标出的结构问题**分流，不是程序能读懂并识别所有平淡问题。

## 2. 实际写作：不要只把概述加长

以下两组都是本次新写的公开合成教学片段，不来自作者的真实小说。概述和展开均为演示设计，**不是旧模型与新模型的生成 A/B**；篇幅不同，不能据此计算提升率。它们只示范方法，不应逐句复制到作品或每次起草都载入。

### 例一：核对记录，而不是让配角直接交代答案

演示边界：账本写备用钥匙 18:00 归还，门禁写保管人 18:10 入楼；只知两份记录冲突，不知哪份错、谁改过。管理员想保全原件并争取共同复核，保管人不愿在未经核实前被认定有问题。允许使用用于记录当前交涉的核对单和笔，它们不提供新线索；不加入监控、真凶、第三份决定性证据或追杀。

**概述写法**

> 陈澄拿出账本，指出时间与门禁不一致。保管人解释了一番，同意明天一起核查。她记下情况，离开了。

**场景展开示范**

> “这里写的是六点。”陈澄把账本转过去。
>
> 保管人没看她指的地方，先看核对单。
>
> “归还时间有误，”他念，“谁说是这本错了？”
>
> “门禁上是六点十分。”
>
> “那就两份一起查。”他把核对单推回来。“这句话，我不签。”
>
> 陈澄的笔还停在签名栏旁边。她原本只差一个签名，就能把这件事交上去。
>
> 她把单子转回来，划掉“归还时间有误”，另起一行写：“两份记录时间不一致，待核。”
>
> “这样呢？”
>
> “你也签。两份都查，原件都别动。”
>
> 陈澄在自己的名字后面写下日期，再把笔递过去。
>
> 他这才签了，在旁边补上“双方到场”。
>
> 她收起核对单。明早，她也得带着原始门禁记录来。

**变化不在辞藻**：陈澄的第一次说法带有预设，对方因此拒绝；她若要取得复核机会，就必须撤回未经证实的判断，并接受两份材料都被核查。人物有不同利益，应答改变策略，结尾兑现“获得共同复核机会”，没有提前破案。划掉的是本次核对单上的判断，**不是改动原始账本**。

这组展开含有新设计的交涉细节，因此只能作为上述合成场景的写作示范。它不是获准套用到真实旧稿的局部补丁；真实作品若原计划没有这些事件，须先作为结构候选确认。

### 例二：日常也可以发生变化，不需要事故

演示边界：女儿想独立做完一顿饭，又不愿承认自己需要指导；父亲愿意帮忙，但习惯接管。没有重病、意外或家庭危机。本场允许创作炒菜、尝味和分工的普通细节，回报是女儿主动请教、父亲把决定留给她。

**概述写法**

> 父亲想帮忙，女儿说自己会做。后来她请父亲指点，两人一起做好了晚饭，关系更亲近了。

**场景展开示范**

> “盐。”父亲说。
>
> “知道。”
>
> 他伸手去拿锅铲。许宁没松。
>
> “你坐着，今天我做。”
>
> 父亲拉过椅子，真坐下了。她翻了两下菜，尝一口，又翻两下。
>
> 他看着她，没出声。
>
> “你刚才说盐，”她问，“是还要放，还是别放了？”
>
> 父亲笑出了声。
>
> “让你先尝。”
>
> 她拿了只小碟子递给他：“那你也尝。只准说，不准上手。”
>
> “有点淡。”他说，“你定。”
>
> 许宁添了一小撮盐，锅铲仍握在自己手里。

这里没有新增悬念；女儿的“独立”从拒绝一切帮助变成能决定怎样接受帮助，父亲也停止接管。回报来自一件小事的相处方式变化，而不是旁白宣布“他们终于理解彼此”。这是一种可选处理，不要求所有温暖场景都这样写。

## 3. 遇到“太平淡”的实际处理顺序

先读真实章稿、计划和相关事实，指出最影响阅读的场面，保留已经有效的部分。没有读到作者作品时，不能把上面的演示诊断冒充对真实小说的结论。

计划已包含值得展开的选择时，说明原文跳过了什么过程，再在已授权范围展开。计划本身没有有意义的得失、回应或变化时，进入 [00 故事设计](prompts/natural-fiction/00-story-design.md)：给出最小的事件调整候选，说明改变了什么、为什么符合这个人物，以及不能改动的事实，等作者确认具体版本再重写。不要再给同一篇流水账做第三遍同义词替换。

正文仍走 [01 写前](prompts/natural-fiction/01-writing-before.md) → [02 审校](prompts/natural-fiction/02-editorial-review.md) → 必要的 [03 修订](prompts/natural-fiction/03-local-repair.md) 与复审。平静、完整收束或低外部冲突不自动构成失败。
