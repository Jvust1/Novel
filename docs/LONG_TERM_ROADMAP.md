# Novel 长期路线图：先证明长篇一致性，再扩大写作能力

- 规划日期：2026-09-22；规划视野：2026-09-22—2027-09-21。
- 性质：十二个月发展建议；未完成事项均为提案，不是当前产品能力。
- 时间口径：以项目正式启用日 T0 起算；阶段窗口是目标，不是固定交付承诺。
- 并行原则：全项目同一时期只投入一个主项目与一个支撑项目；本库未入选时保持维护/孵化。
- 推荐角色：以实际写作需求驱动的质量实验项目；完成盲评前不扩建复杂客户端或多 Agent 平台。
- 数字说明：现状表属于已读取证据；其他规模、阈值和预算规则均是建议验收标准。

## 1. 目标与边界

建立适合中文长篇连载的写作助手，让作者能够控制场景、人物、知识边界、文风与局部修改。
产品价值应体现为读者更想继续读、人物行为更可信、前后矛盾更少、作者修稿成本更低。
长篇记忆服务故事和人物，不以接入向量库、知识图谱或更多模型作为成果本身。
默认保留作者决定权：先确认场景计划，再写正文；修订后的正文应经过复审。

不把无人值守批量生成百万字作为首要目标。
不把 AI 味启发式分数当成文学质量、人类作者身份或版权安全的证明。
不把某位作者名字当作完整风格配置，不把参考原文片段作为仿写素材拼接。
不把原稿、参考书正文、模型凭据或完整用户写作目录提交到 GitHub。
暂时延续本地 Streamlit 原型，等质量与使用流程成立后再判断是否换宿主。

## 3. 贯穿全年的工程原则

- Context、Plan、Draft、Review、Repair、Memory Update 保持责任分离。
- Canon、Active、Recall 各有预算，不能用无限追加正文替代记忆管理。
- 人物所知、未知、误解与读者所知分开，新增知识必须有章节证据。
- 模型提出抽取/修改候选，确定性的代码维护锁定、幂等与状态一致性。
- 默认最多一轮自动修复与复审；仍有问题交作者决定，不进入烧费循环。
- 作者已确认的计划、人物锁定和原稿版本优先，不被自动生成覆盖。
- 任一新模型、新检索方法、新提示协议都需要独立版本与可比对照。
- 冻结用例、第一次真实结果与失败记录保留；观察过的用例不再称 unseen。

## 4. 阶段 A：T0 后 0—30 天，把现有证据评完

### 交付内容

- 恢复首次真实运行的 6 篇结果、配置、评分表和身份记录，确认其可长期恢复。
- 完成 6 篇 × 12 维的人工评分，先盲化变体标签，再记录评分理由。
- 记录 B−A 差值、逐篇差异与样本局限，不只提供平均分。
- 复核 PR #13 的差异与 CI，评估已错序历史摘要是否需要独立迁移方案。
- 整理当前状态中已被后续记录取代的事项，建立唯一下一任务。
- 给现有模型调用加可观察的次数、耗时、输入输出量和成本记录方案。
- 建立知识泄漏、时间线、伤势、道具与人物锁定的缺陷分类。

### 验收提案

- 原始 6 篇结果全部可恢复，评分格 72/72 完整；空缺不能以零分代填。
- 每个连续性问题至少指出人物/事实、冲突片段和对应源状态。
- 评分人信息用适当匿名标识；只有一位评分人时明确主观性，不冒称多人共识。
- 若有第二位评分人，独立评分后报告分歧；不要求两人“调成相同”。
- 所有模型质量结论限定在该模型、版本、题材和当前样本范围内。
- 首轮结论至少给出“保留记忆层/修改记忆层/证据不足”三者之一及理由。
- 本阶段不因评分难而先增加 RAG、Agent 数量或新 UI。

### 依赖与暂停点

依赖首次结果包可读、评分时间和真实模型配置记录。
若历史结果找不到，先记为证据恢复阻断；新运行另设 run ID，不能补写成第一次运行。
没有人工评分时，允许修复确定性代码错误，但不发布文学质量改善结论。

## 5. 阶段 B：T0 后 31—90 天，建立一致性与作者控制闭环

### 交付内容

- 在新版本用例中建立至少 30 个可判定连续性陷阱，包含知识、伤病、物品、时间和身份。
- 抽取候选包含证据章节与原文位置；未知角色、无来源知识和锁定角色修改进入待确认区。
- 人物知识边界审查区分“真实获得”“推测”“误解”“读者知道”。
- 加入作者确认的局部修订预览，显示将改变的段落和关联人物/事实。
- 对确定性状态约束与模型审校分别统计，避免混为一个“正确率”。
- 建立稳定保存、恢复、重复点击和中断重试的回归。

### 验收提案

- 重复写回同一抽取 10 次，不增加重复事实、重复未应用记录或改变摘要顺序。
- 锁定人物、已确认原稿和未经确认的计划在相关回归中不被覆盖，阻断错误为 0。
- 30 个陷阱逐条人工标注；同时报告漏报与误报，不只报召回率。
- 初始目标：严重矛盾召回率至少 90%、误报率不高于 20%；未达标仍可保留为辅助建议。
- 至少完成一个 10 章连续写作实验，记录前后状态而非只比较单章。
- 修复后复审能区分已解决、未解决和新引入问题；仍失败不会自动无限重试。
- 提示协议升级不能修改旧基准的标签和结果。

### 依赖与暂停点

依赖阶段 A 的人工评测结论、可验证原稿来源及作者确认流程。
若模型知识归属持续不可靠，将该类回写降为人工确认，不用更多自动回写掩盖问题。
若既有存储需要迁移，先做只读迁移预览与新副本验证，不能覆盖唯一原稿。

## 6. 阶段 C：第 4—6 个月，证明检索或角色路由的增益

### 交付内容

- 以连续写作的真实失败归因决定是否开展检索实验。
- 若主要失败来自历史事实未被召回，再比较关键词/结构化检索与向量检索。
- 若主要失败来自审校能力，先比较同模型与独立 reviewer 的质量/费用。
- 每次只改变一个主要变量，保持题材、模型条件或预算边界可解释。
- 建立单章、单项目、单月人民币成本统计与停止机制。
- 加入更长篇章的伏笔追踪和人物状态变更视图，方便作者纠错。

### 验收提案

- 新评测至少覆盖 3 个题材，每题材至少 4 组匹配比较；小样本结果不外推成通用结论。
- 检索候选的事实来源可追溯率 100%，无证据的内容标成推测或不使用。
- 先登记采用阈值；建议关键一致性维度平均提升 ≥0.4/5 且没有新增严重知识越界。
- 同时报告作者偏好、修稿分钟数、长度差异和每千字成本，避免只看模型打分。
- 成本增长建议不超过已确认基线的 50%；超出时需证明修稿时间或质量收益足以补偿。
- 新方案没有稳定收益时保留简单基线；“做过实验但不采用”属于有效成果。

### 依赖与暂停点

已有 D-007 的评测前提未解除前，不把 RAG 写成必做开发里程碑。
真实端点需可用且预算已设定；本地模型容量按实际显存规划，下载位置遵守 D 盘规则。
需要新付费资源时先明确人民币上限，不假设用户持有美元支付方式或无限额度。
本规划不调用模型、不购买订阅，也不把未来预算视为当前付款授权。

## 7. 阶段 D：第 7—12 个月，形成可信的长期写作工作台

### 交付内容

- 建立作者可理解的章节、人物、伏笔和修改历史视图。
- 支持项目恢复、版本导出和来源索引，明确当前定稿与实验稿。
- 在实际连载项目上进行至少 4 周小范围使用观察。
- 根据真实交互瓶颈决定是否继续 Streamlit，或以适配器迁移宿主。
- 整理写作模式：快速草稿、精修与仅审校，明确每种模式的成本和边界。
- 建立每次版本变更的质量回归，保护已有文风和人物声线。

### 验收提案

- 至少一个 20 章项目有完整状态链与可恢复材料，不要求全自动生产。
- 同一原稿在升级前后可查看差异，作者确认前不会替换定稿。
- 30 个核心工作台流程全部可恢复，包括重启、取消、重复操作和模型超时。
- 在同一任务上，作者修稿时间相对建立的基线下降，且人工质量评分不降低。
- 若新宿主不能显著减少操作成本，不进行全面重写。
- 可说明每项自动建议依赖哪些原稿事实，以及哪里仍需要作者判断。

## 10. 指标、预算与停止规则

| 指标 | 定义 | 提案 |
| --- | --- | --- |
| 连续性严重缺陷 | 与已锁定事实/人物知识直接矛盾 | 每章统计，趋势下降且回归为 0 |
| 叙事质量 | 既有 12 维 1—5 分 | 人工盲评，保留题材差异 |
| 作者修稿成本 | 达到愿意保留的版本所用分钟 | 与同作者、同类任务基线比较 |
| 参考近似复用 | 本地签名/片段警报 | 人工检查；不能冒称版权判定 |
| 每千字费用 | 实际调用费用/有效定稿字数 | 人民币记录，失败重试计入 |
| 修订稳定性 | 修正目标外的事实/声线漂移 | 同时报告目标修复与副作用 |
| 恢复可靠性 | 重启、中断、取消、重复写回 | 原稿不丢失，状态可解释 |

建议将预算分为单次运行上限 C_run 和月度上限 C_month，数值由用户实际可承受额度填写。
未设置的新付费预算按 0 元处理；已有订阅、本地模型与付费 API 的计费边界分别记录。
真实账单优先于估算；无 token 或价格记录时标 UNKNOWN，不把缺失费用算成免费。
超时、拒绝、格式失败和重试必须计数；预算耗尽时先保存结果，再停止新增调用。
模型质量不达标时可以缩小任务或改成人工审校辅助，不靠无限重试“磨到满意”。

## 11. 风险与路线重评

- 首次结果无法恢复：暂停基于其结果的质量结论，先补证据恢复。
- 评分者知道方案身份：注明盲评失效，后续另设盲化样本，不篡改原评分。
- 小模型把读者知识写成人物知识：暂缓自动回写，增加来源审核。
- 越过作者锁定或覆盖原稿：阻断发布，先修复存储与确认流程。
- 生成更长但没有更好：不因字数达标认定质量进步。
- 两轮 A/B 未见稳定收益：停用新增复杂模块，回到最简单的可解释基线。
- 费用超过预算或端点不可用：保存未完成 run，不能改成“运行通过”。
- 旧分支与主线冲突：保留历史，做选择性移植设计，不进行批量合并或历史清理。

## 12. 跨库边界与复盘

Book 的教材抽取经验可用于来源定位，但教材内容不能自动进入小说参考语料。
mygpt 可通过用户显式选择的接口打开写作任务，不默认读取完整手稿。
Invest 与 NCMCM 的评测纪律可参考，模型执行权限、预算与结果仍由本库独立管理。
AutoFlow 只负责明确受控的操作辅助，不替作者作发表、发送或付费决定。
GitHub 保存代码、Schema、治理、派生风格特征和评测索引；Drive 保存原稿、大结果包与正式快照。
每月复盘质量、修稿时间、费用、状态可靠性和复杂度；每季度重新比较简单替代方案。
保持一个明确主实验，不同时更换模型、提示、检索和评分协议。
连续两个月缺乏实际写作需求时降为维护，保留可恢复基线，不为活跃度制造功能。
