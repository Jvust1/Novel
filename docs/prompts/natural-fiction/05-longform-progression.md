# 长篇推进：让章节之间有积累

对应 `story-craft 1.2`。在 00 / 01 / 02 / 03 中读取本阶段部分；不是新增一次模型请求，也不自动把候选稿变成正式故事。只审文风的任务不因此扩大为改纲。

## 计划前：先找本章承接什么

读取已确认大纲、本章目标、人物当前状态、相关已接受历史和读者信息揭示账本。摘要用于定位与有限核对；需要前章细节时回到原件。记录实际读到的章节与版本，不把工程状态、候选摘要或旧聊天印象当作历史。

围绕这几件事安排本章：上一章的哪项选择改变了现在的条件；人物因此需要改用什么办法；哪些代价、能力和关系仍然有效；本章兑现什么；哪条未解决线索本次推进，哪条按大纲保留。不是每章都必须承接紧邻一章，支线切换、时间跳跃、独立单元和尾声按原结构处理。

已有 `ChapterPlan` 足够承载这些内容，不另造必填账本：objective 说明眼前目标怎样从相关历史而来；opposition 体现环境或对手对先前行动的反应；choice / cost / state_change 记录当前选择怎样继续改变局面；chapter_promise 明确本章的实际回报；tension_curve 标明本章是验证、兑现、消化还是开启下一步，不强制固定轮换。

## 避免“换皮任务”

比较相关近章的目标、办法、回应和结果，而不是数相同词语。有意重复的仪式、独立事件或日常可以保留；真正的问题是换了人名地点，人物仍用同一种办法、交同一种代价、得到同一个结果，没有新理解或新选择。

在作者授权的策划空间内，优先改变利益关系、可用办法、责任或胜利条件，而不只是换更强敌人。对手和配角也记得前面的事；既有成长应改变人物做法。人物可以退步，但要有成立的触发，不为制造争执把上一章成长清零。

**合成策划示意，非用户章稿或模型对比结果：**

```text
松散串联：找到一人 → 得到一个疑点 → 换个地方再问一人。
有积累的串联：过早指控让对方拒绝合作 → 主角撤回未经证实的判断，
换得双方到场复核的约定 → 下一章真正落实复核，使用已获准的材料，
并承担自己也必须出示原件的责任，而非重新演一遍争取机会。
```

这不是要替任何真实作品追加事件；原计划没有的交涉、责任或揭示，先作为结构候选取得确认。

## 起草：不重播前章，不抹掉回报

直接进入已经改变的处境，必要定位只给理解当前场面所需的信息。旧读者已经看过的全过程不再次铺陈；承接不等于把前章摘要放进开头。既有代价要实际限制选择，既有收获要真的可用，关系变化要影响行动或应答。

兑现不等于所有谜团立刻解决。本章获准验证的疑点、完成的承诺或推进的关系要落地，不能只把“秘密更大”再说一次。高潮之后保留满足、失落、尴尬、幽默和收拾残局；恢复章与结局不必加危机。重复出现的事物可以获得新意义，但不能因此编造旧场景或逐字对白。

起草不得为避免重复偷改已确认计划。需要改事件、关系、能力、时序或揭示范围时，回到 00 提出最小变更，等作者确认具体版本。

## 审校与修订：历史依据也要传下去

把本次相关历史连同计划、正文、作者要求和文风卡交给初审、修订和复审。分别检查人物状态无因归零、旧误会复活、重复过关、承诺拖欠、候选信息冒充旧事实，以及回忆段落中没有来源的细节。

问题需要当前正文定位和相关历史依据；提供过 chapter_id / revision 时注明它们。excerpt 仅摘当前正文，reason 中区分摘要与原件，不拿摘要伪装前章逐字引用。历史没提到某事，不代表它从未发生；同标识不同版本或摘要与事实锁冲突时，保留冲突、核对原件，不自行选择较新时间覆盖。

当前计划已正确、正文表达有遗漏时才局部修。计划本身重置人物或需要改变事件才能兑现时，用既有 `story_structure_requires_replan` 退回计划。与单章审校合计仍最多五个重要问题；没有依据就标覆盖不足，允许零问题，不新增质量分数或自动接受。

## 程序与对话边界

程序通过 `story_craft.py` 把 `story_progression.py` 对应阶段规则送入原提示工厂。共享引擎将调用方提供的 `recent_summaries` 传给两个编辑依据构造器，初审和复审复用同一份上下文；不会检索新档案、自动对账或写回正式记忆。历史原字段、顺序和不同版本保留，没有截断、去重或“最新版本胜出”。

`history_scope` 只声明这个构造器实际做了什么：有摘要、空列表或未提供；它不验证作者接受，也不读回前章全文。调用方仍需通过项目既有的已接受历史重建流程选择来源。JSON 编码不是提示注入隔离或秘密过滤器；包括摘要中可能出现的未公开信息仍受读者信息边界约束。

没有实际执行器时按以上文本协议工作，不声称运行了程序。旧会话需重新读取本文件；是否进入 main，以真实合并回执为准。验证与限制见 [升级记录](../../STORY_CRAFT_PROGRESSION.md)。
