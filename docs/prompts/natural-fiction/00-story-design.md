# 故事设计：先让人物的选择值得读

版本：story-craft 1.0。Novel 原创协议，不取代事实锁、类型文风卡或作者确认。使用位置：Context → Scene Plan；“小说太平淡”先检查结构，再处理措辞。只有已确认的计划才能进入正文，候选不自动写入记忆。

## 输入与权限

读取 TASK（新章策划 / 旧章诊断 / 已授权结构改写）、已确认设定和人物、上层大纲、本章目标、主类型/语气、有关的已接受历史及读者信息账本。标明故事与计划版本、已读资料及缺口。只审文风的任务不得据此扩大为改剧情。

新章策划可以在授权空间提出事件、阻力和细节候选；旧章结构修改先列原问题和拟变更。不能借升级重设人物、改结局、添加关键能力或泄露未获准真相。来源不足时做有限诊断，不假装看过真实小说；不要求为升级工程先提供私有作品。

## 1. 确定这一章的阅读价值

用具体问题代替“推进主线”：读者在乎这个人物争取什么，为什么现在在乎，这章结束会获得哪种满足或新的理解？可以是揭开一个疑点、看清一个人的选择、关系前进一步、一次喜剧错位、付出代价后的成功，也可以是危机后的安宁与告别。

区分长线悬念和本章回报。本章应该真正发生一项有意义的变化，而不是只有新的谜语。已有承诺的回收必须能定位到已读且已接受来源；没读到历史就注明不能核验，不臆造“前文早有伏笔”。已确认计划要求完整结束时，不为续读强加陌生人、黑影或威胁。

## 2. 把人物卡变成行动

围绕关键人物落实：当下可观察的目标；这个目标背后的私人需要；已有恐惧、缺点或关系怎样妨碍他；他习惯采取什么办法；什么回应迫使他调整。角色可以犯错、自欺或嘴硬，但错法须由已给的经历、认知和利益解释，不能为了转折集体降智。

配角有自己的利益与底线，不只是递送线索、夸赞主角或拦路的人。对话中有人试探、有人回避、有人讨价还价、有人示好；反应改变下一步策略。亲密和日常也可以只是一句终于说出口的话，不必变成争吵。

## 3. 设计有代价的因果链

关键场景写明：

```text
谁想要什么，为什么对他重要？
谁或什么阻止他，对人物行动如何回应？
有哪些真正可行的选择，各自会失去什么？他为什么选这一条？
前态 → 尝试/回应/调整 → 后态；结果怎样改变下一场目标或条件？
读者此刻知道什么，人物知道什么，还有什么不许揭露？
```

选择不是“正确答案与蠢办法二选一”；代价也不必是生命，可以是时间、体面、信任、机会或承认自己需要别人。不要每次胜利都附带同一种惩罚，不强迫所有场景写两难。恢复、陪伴和获得帮助也是真实变化。

相邻场景应尽量能用“因为上场这样选择，所以现在……”连接。可互换且没有影响的办事场景考虑合并；但有关系建立、情绪消化或空间转换作用的段落不机械删除。后果需延续，不能下一场恢复原状；升级阻力优先改变可选方案、关系或判断，而不是一味增加敌人数目。

## 4. 安排节奏、铺垫与兑现

把篇幅给关键尝试、回应和决定；不要列一串事件后用“几经周折”略过。以本章功能决定快慢：试探可以慢，重复手续可以快，高潮后容许沉默、欢喜、尴尬和收拾残局。不能全章等强度，也不要求固定三幕、反转数量或每段钩子。

反转可有可无。有反转时，应来自已有证据或行为的新解释，回看能理解；不能临时新增规则救场、故意隐瞒视角人物已知的信息或把猜测硬写成事实。伏笔写清已知铺垫、当前推进/兑现和仍未公开部分，仍受揭示账本控制。

类型决定回报，不统一套悬疑：日常看关系与生活选择，言情看接近与边界，成长/冒险看能力运用和实际代价，悬疑看验证与公平信息，科幻看约束下的选择，历史/武侠看制度、人情和承诺，恐怖看既有安全规则如何失效。已有作品文风和作者决定始终优先；这些不是套路配额。

## 5. 交付可写、可审的计划

沿用当前计划格式：视角、时间地点、目标、阻力、选择、代价、状态变化、信息释放、伏笔与结尾期待。加一段短说明：这章兑现什么、哪里展开、哪里压缩，以及需作者决定的结构变更。不得把这些说明混进正文。

用户明确要“更不平淡”且确有结构选择时，可以给两到三个**真正不同的推进候选**，说明各自怎样改变人物选择与阅读体验，而非同一剧情换措辞。资料和方向足够时直接推荐一案，不为凑数量扩大故事。作者确认明确版本后再进入 01。

程序使用现有 `ChapterPlan` / `SceneBeat` 字段：chapter_promise 承载本章承诺与回报，tension_curve 承载节奏，choice / cost / state_change 承载得失和因果。不另造必填字段，不把文档卡直接当作新 Schema。程序只返回一个候选计划，不增加模型请求。

## 6. 对平淡问题分层处理

**表达问题**：计划中有明确的博弈、选择或关系变化，但正文跳过、重复解释或把所有人写成同声。给出原文定位、已有依据与获准修复范围，交 03 局部修复。

**结构问题**：计划本身只是见人、听说明、走到下一地点，缺有意义的选择或变化；修好需要改事件因果、结局或揭示顺序。标记 `story_structure_requires_replan`，指出需要作者决定的最小计划变更；保留原稿，不能偷偷加料。

**不是问题**：安静、克制、温暖、喜剧、哀伤或完整收束已实现本章功能。保留，不因为没有追杀或反转而判失败。

判断必须依据这次实际读到的正文与计划。关键词、句长、模型自评分或程序测试通过都不能证明故事已经好看；最终用同条件试写、读者比较和作者反馈验证。
