# 已保存故事设定变化后，先核对再写作

本轮原创离线界面反例确认了可选本地工作台的两个旧行为：另一会话已保存新题材或世界规则，旧会话仍按旧设定生成并保存候选；旧会话点击保存设定，还会覆盖新版本并丢掉新增作者字段。正式已接受档案和记忆双确认另有来源检查，本轮未发现这些确认可被绕过。

## 当前保护

- 加载项目时一起读取完整 `story_bible.json` 与内容指纹，未知作者扩展字段也参与核对。文件不存在与已保存空对象分别绑定，格式错误不会被当作空白来源
- 生成计划、正文、审校、局部修订与复审，沿用已有请求守卫，在发送前和响应后检查固定的已保存设定来源；最终保存候选前也在原项目锁内核对。其他会话改变来源后，旧会话停止调用和发布
- 保存故事设定前，在同一个原项目锁内比较原来加载的来源。冲突时不写故事设定或平面总纲，保留当前编辑。成功写入并真实读回后才更新会话基线
- 已有待写计划绑定其故事设定保存版本。保存了不同版本后，旧计划不能直接继续写正文；明确重新生成计划，或重新载入所选大纲章节并核对后继续
- 切换项目后返回缓存草案，仍保留原基线，不把另一会话的新来源悄悄配给旧编辑

遇到冲突，先用“下载当前故事设定与总纲草案”保留未保存编辑，再在新会话读取当前项目、核对两版并决定如何整理。不会自动合并或覆盖。下载内容是作者草案，不是正式接受记录；人物、层级大纲、正文及其确认继续走各自既有流程。

## 明确保留的边界

这次没有增加多文件事务。原“保存故事设定”按钮依次写故事设定和**平面总纲**，两份文件各自原子发布。第二份写入或读回失败时，第一份可能已经写成；错误提示不承诺回滚。当前界面编辑与基线保留，先读实际文件核对后再决定下一步。仅当故事设定内容已改变时，旧基线会阻止依赖它的写作；同值设定写入、重启或新会话不能据此获得完整多文件恢复保证。

单独改变平面总纲而没有改变故事设定，并没有新增独立的平面总纲 CAS 保护。已保存**层级大纲**继续使用已有的独立绑定和明确刷新机制。未保存的设定编辑沿用原工作台行为，本轮没有为所有界面字段新增统一接受状态。

沿用 ProjectStore 项目锁与单文件原子写入，适用于可信本地目录和合作写入者。它不是跨设备锁、Drive 事务或恶意进程竞态沙箱。主入口仍是 GPT + GitHub 插件读取规则与作者指定的私有档案，不要求安装本地程序；本地候选、正式接受正文和确认记忆保持不同状态。

## 验证与来源

验证使用原创合成资料、真实 Streamlit AppTest 控件与 HTTPX MockTransport，检查旧来源、每个 HTTP 阶段、最终发布、保存冲突、失败读回和跨项目恢复。保留原依赖、许可证、静态门禁和完整双 Python 测试；精确结果以[候选记录](../governance/story_settings_candidate.json)、已发布 Draft PR 的精确提交 CI 和实际解包回执为准。

本轮没有新增依赖、复制新上游代码或调用付费模型。外部 AI 对公开摘要的设计咨询不等于读取源码、运行测试或安全保证。预算、记忆确认、接受历史、文风保存、参考解码、PDF 与人物来源修复继续保留。
