# 风格资料一致保存与恢复

Style Lab 原来依次写入来源列表、综合 Style DNA 和参考签名，并在这些文件成功之前修改会话。实际故障复现中，第二个文件写入失败后，当前页面有完整风格，重启却只剩来源列表。现在三项资料通过同一次有界保存、真实读回和统一加载保持一致；失败时不把半成品当作当前风格继续写作。

## 在 GPT 中如何处理

GitHub 插件用于读取本协议，不代表执行了本地保存器。作品、参考原件和派生风格仍放在作者指定的私有位置。只有取得实际文件、有可用执行器并读回核对后，才能声明程序保存或恢复成功。没有执行器时，保留待保存内容、当前版本和阻塞原因，不要求作者安装本地工作台，不编造回执。

本次只加强已有本地 Style Lab 和 ProjectStore 的保存路径，不提供 Drive 多文件事务。故事档案、人物、章纲、作者正文接受、记忆确认和日志归属仍使用各自已有门禁；风格保存回执不构成任何作者接受或身份认证。

## 工作台操作

1. 完整读取参考原件后，沿原分析链提取高层风格与签名。分析前先核对当前风格文件是否仍是本会话实际加载的版本；另一会话已修改时先重新读取
2. 分析结果先形成独立待保存请求，不先追加到当前会话。来源、名称、权重、编码选择、语义分析开关和备注共同绑定本次操作
3. 三个目标文件完成后逐项读回，发布不可变回执，再更新当前会话。失败不等于回滚，界面保留同一待保存请求
4. 使用“重试上一项风格保存”保存已分析结果，不重复分析或请求模型。改变输入后不能拿旧请求冒充新输入；可恢复原选择，或“重新读取已保存的风格”核对真实磁盘状态
5. 待保存请求未解决，或会话比磁盘旧时，后续写作、审校和发布入口暂停。重新读取保留不相关的未保存章纲、人物和正文草稿；它不会替作者接受它们
6. “清空并保存当前项目风格库”明确保存空来源、空综合风格和空签名，重启后仍为空。它和新增使用同一版本检查与恢复流程

切换项目再返回时，风格重新从本项目磁盘一致加载；其他未保存写作草稿仍按原有项目缓存隔离。生成入口在调用模型前核对当前风格，在正文写入前再次核对；旧风格会话不能静默覆盖较新风格资料。

## 固定保存协议

三个固定目标是 `styles/style_profiles.json`、`styles/style_dna.json` 和 `styles/reference_signature.json`。同一项目锁内读取完整旧字节及 SHA-256，以乐观版本检查拒绝旧会话。保存记录只允许这些目标，保留完整旧、新内容与身份绑定，限定总大小；不接受重复 JSON 键、非有限数、错误形状、路径别名或错误恢复身份。

每次新的明确操作产生独立请求标识，重试保留同一标识。该标识与完整请求回执绑定；同一标识换内容会被拒绝。新增 A、清空、再有意新增同一 A 是新操作；重试旧 A 的历史成功回执不能复活已经清空的资料。

实际文件写入沿用既有 boltons 原子保存源码和原生项目锁。先发布并核对保存意图，再逐项发布、读回三个文件，最后独占发布回执并核对，随后清理意图。进程中断后，合作读者要么完成这同一固定请求，要么遇到独立变更或损坏后停止并保留证据。已发布回执只证明历史操作完成，清理重试不得用旧内容覆盖后来的修改。

记忆候选读取及记忆提交识别待恢复风格事务，不能绕过普通读取入口而抓取半套配置。互相冲突的风格、提取或记忆恢复记录不自动合并；保留后核对。

## 旧资料与手工覆盖

完整有效的旧三文件按原字节读取，不在启动时迁移、重写或重新计算。旧 fingerprint 缺少后来增加的字段、缺少编码报告或带未知扩展字段时继续保留。未知综合风格扩展字段在后续新增时保留；旧空白显示名称保留，但新增来源需要明确名称。

手工覆盖的综合 Style DNA 不因与来源自动融合值不同而被当作损坏或改回。新增来源若会覆盖这些已知维度，需要先核对，当前有限入口会拒绝直接替换。完整空库有效；缺少配套文件的旧资料不能猜补丢失的综合风格或参考签名，须保留原件并明确对账。

## 验证与边界

真实 AppTest 覆盖第二文件失败、原会话不变、无重复模型分析的重试、重启、清空、双会话旧版本阻止和项目返回。独立对抗测试覆盖坏意图、重复键、非有限值、旧扩展字段、人工覆盖、请求重绑、历史重试与混合事务。真实子进程在意图、三个目标及回执发布后立即退出，恢复后得到完整同一组；两个并发进程使用同一旧版本时仅一个获准提交。

这仍是可信本地目录内合作读写者的有限恢复协议，不是任意多文件事务、恶意目录竞态沙箱、跨机器锁、Drive 保存协议、所有断电场景保证或原生 Windows 验收。字节摘要并非用户认证，也不证明文学质量。完整矩阵与精确远端验证见 [候选记录](../governance/style_save_candidate.json)；实际开源复用见 [来源说明](upstream/style-save-2026-10-01.md)。
