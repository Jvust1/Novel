# Project North Star

## 最终产品形态

Novel 的最终形态不是“自动续写器”，而是一套面向中文长篇网文的 **原创小说生产与编辑系统**：

1. 用户提供若干部代表小说、题材偏好、受众、想写的方向或一句创意。
2. 系统从参考文本中提取三类可解释特征：
   - **Style DNA**：句法节奏、段落密度、对白比例、叙事距离、动作/心理/环境配比、词汇层级、留白方式、角色声线差异等。
   - **Story DNA**：开篇切入、冲突循环、爽点/回报节奏、信息释放、人物关系推进、伏笔方式、章末钩子、卷级升级结构等高层剧情模式。
   - **Market DNA**：目标平台与题材的书名/简介/标签/开篇承诺、章节节奏、更新结构与读者反馈指标。
3. 系统不直接拼接或改写参考小说，而是基于上述 DNA 重新构造原创世界、人物、核心矛盾、事件链、伏笔链与长篇结构。
4. 通过 `Context → Scene Plan → Draft → Review → Repair → Re-review → Memory Update` 持续生成，并允许作者在每个关键节点介入、编辑和锁定。
5. 最终输出应达到可直接进入番茄小说等中文网文平台发布流程的质量，并可根据发布后的真实数据继续调整后续卷纲、节奏和看点。

## 第一优先级：读起来像真正作者写的

“降低 AI 痕迹”不是靠随机错别字、故意语病、改标点或针对某个检测器做对抗，而是让文本本身具备稳定的人类写作特征：

- 句长、段长和信息密度有自然波动，不机械均匀。
- 人物有不同的说话习惯、认知边界、偏见、遮掩、误解和关系历史。
- 行为、情绪和信息通过场景自然显现，不反复总结解释。
- 允许冷句、短句、停顿、留白、未完成表达和不对称结构，但不能靠低级错误伪装。
- 描写服务于行动、关系、信息或节奏，不为了“文学感”堆砌。
- 每章都应有局部独特细节，而不是模板换名。
- 修订优先做针对性的作者式局部编辑，而不是整章统一洗成一种“漂亮 AI 文风”。
- 长篇中的小习惯、关系变化、知识差和长期后果必须延续。

第三方 AI 检测结果只能作为辅助信号，**不能作为唯一优化目标，也不能承诺 100% 不被任何检测器识别**。真正目标是：人工盲读时文本自然、原创、角色可信，并且无需大规模人工重写即可发布。

## 商业目标：提高“爆款概率”，不承诺爆火

Novel 要系统性优化影响网文传播的可控变量：

1. **开篇承诺**：前三章快速建立题材卖点、主角问题、核心期待。
2. **持续阅读动力**：每个场景有目标/阻力/选择/代价，每章有新的状态变化。
3. **看点密度**：爽点、反转、关系推进、信息释放、危机和回报按题材配置节奏。
4. **章末拉力**：不能只靠机械断章，要制造新的问题、选择、损失或即将兑现的承诺。
5. **人物黏性**：角色欲望、缺陷、秘密、关系变化形成长期追更动力。
6. **长线升级**：每卷提高问题层级，但不能无理由通胀。
7. **平台适配**：根据番茄等平台当前公开规则、题材趋势和作者后台数据调整书名、简介、开篇、章节长度、更新节奏和后续剧情。

系统目标是提高签约、推荐验证、阅读留存、追更和传播的概率；**不把“必爆”作为可承诺结果**。

## 质量优先级

从高到低：

1. 是否让目标读者想继续读。
2. 是否像真实人物在做选择，而不是剧情拖着人物走。
3. 是否原创，且没有参考小说的句段、人物或事件链换皮。
4. 长篇连续性是否可靠。
5. 是否具有自然、稳定而非模板化的作者感。
6. 风格是否统一但不僵硬。
7. 是否符合目标平台和题材的商业阅读节奏。
8. 是否方便作者介入、重写和长期维护。

## 参考小说使用边界

允许学习：
- 高层文体统计与节奏规律。
- 叙事距离、对白密度、心理/动作/环境比例。
- 开篇方式、冲突类型、爽点间隔、悬念结构、伏笔策略等抽象模式。
- 多本作品共同出现的题材惯例和读者承诺。

禁止作为产品目标：
- 复制原句、长片段或特色表达。
- 仅替换人名/地名的情节换皮。
- 复制某一本书的角色关系网、世界设定或事件顺序。
- 把某位作者名字当成唯一风格指令。

系统应保留非可逆参考签名和相似性检查；接近某一参考来源时必须重构，而不是继续贴近。

## 最终流水线

`Reference Pack → Style DNA + Story DNA + Market DNA → Original Premise → Story Bible → Character Web → Long-term Outline → Volume/Arc Plan → Chapter Plan → Draft → Human-feel Review → Continuity Review → Originality Review → Local Repair → Re-review → Memory Update → Release Pack → Platform Feedback → Next-arc Adaptation`

## 最终完成标准

Novel 只有同时满足以下条件，才算接近最终形态：

- 可一次导入多本参考小说并形成可编辑的 Style / Story profile。
- 能从 profile 生成多个**原创**题材方案，而不是参考书改写方案。
- 能维护至少数十万字级别的角色、事实、时间线、知识边界和伏笔连续性。
- 人工盲评中，“AI 味/模板感”稳定处于低水平。
- 参考重合检查和剧情衍生检查无高风险项。
- 前三章、单章、单卷和长线四个层级都存在独立质量评测。
- 可以生成适配番茄发布的书名候选、简介、标签建议、章节正文和发布前检查包。
- 可以导入真实平台表现数据，用于调整后续剧情，而不是发布后仍按初始大纲僵硬续写。

## 明确不做

- 不以“无人值守生成百万字”为第一目标。
- 不用全文硬塞上下文替代结构化记忆。
- 不把多 Agent、RAG、知识图谱数量当作质量本身。
- 不用错别字、乱码、异常标点等方式做检测器对抗。
- 不承诺任何作品一定爆火。
- 不牺牲原创性换取对参考小说的表面相似度。
