# 存稿与评测证据保护

本次改动保护执行器中的本地项目文件：章节正文、JSON、摘要 JSONL，以及评测输出和人工评分表。它接入已有 `ProjectStore`、工作台、上下文读取和 benchmark 入口，不要求 GPT 写作用户安装本地程序。GitHub 文件访问仍不等于执行 Python；Drive 的真实写入和读回继续由实际可用工具完成。

## 实际复用

- 保留并适配 Novel [PR16 的路径约束与锁内读改写](https://github.com/Jvust1/Novel/blob/2b5e23fe3ba238ae6046dad125dd7d09847db13d/novel_ai/storage.py)，与此前 PR13 的稳定摘要位置规则协调，不重复引入备份界面
- 直接复用 [boltons AtomicSaver 源码](../third_party/boltons/NOTICE.md)，固定提交 `4e5faa3d7e4008d89e0d8bf1ea87b6d9a061a16d`，2026-10-01 核实 6,932 星
- 完整许可证、原始源文件、上游测试快照、改动行范围和 SHA-256 留在 `third_party/boltons/`。实际许可证是 BSD 风格三条款；GitHub 的元数据标签为 NOASSERTION，不混为自动识别的 SPDX 结论
- 运行时只用 Python 标准库，无新包、数据库、服务、凭据或模型调用

调用链：`ProjectStore / eval.py → atomic_save → 临时完整文件 → 文件同步 → 原子替换或不覆盖发布 → 支持时同步目录`。保留的完整上游文件是来源证据，不作为未使用的运行库加载。

## 普通读写边界

所有项目相对路径先校验再读取/写入。拒绝绝对路径、父目录回退、路径别名、反斜杠/盘符、过长片段、跨平台设备名，以及目标和祖先中的符号链接/可识别的 junction。内部锁与恢复记录不能通过普通内容 API 覆盖，包括大小写别名。历史记忆目录在列目录前也必须经过校验。

JSON、正文和 JSONL 都先完整序列化，再使用同目录私有临时文件。发布前失败时旧完整文件保持可读；发布后发生目录同步等错误时，新完整文件可能已经可见，不能把异常说成“肯定没保存”。先读回确认，再决定是否重试。非法 JSON 数值和不能序列化的内容在打开输出前拒绝。

项目级锁同时串行化本进程线程和配合协议的本地进程。锁文件不删除，避免替换 inode 产生两把锁；嵌套调用使用同一规范路径的重入锁。POSIX 使用 flock，Windows 分支使用原生字节锁；本次实际测试在 Linux，未声称原生 Windows 验收通过。不支持的平台、继承旧锁环境的 fork 子进程会明确拒绝，应使用全新启动的解释器。

损坏 JSON、摘要或历史记忆会给出错误，保留原件，不以空记忆掩盖损坏。锁不是跨会话旧版本自动合并：普通整文件更新仍由调用者决定内容，不能把串行写入说成通用乐观并发控制。GPT v1/作者变更封套原有的版本和实际文件哈希要求保持独立。

## 章节抽取与摘要的中断恢复

`save_extraction` 涉及“本章抽取 JSON”和“摘要索引 JSONL”两份文件。只把每份文件原子写入，仍可能在两次写入之间中断。本次为这一个固定场景加入受检查的恢复意图：

1. 在项目锁内，生成完整抽取和新摘要；原有章节保持原位置，重复同 ID 摘要折叠，新的章节才追加
2. 对两份现有文件计算实际字节哈希，记录旧/新哈希与完整新内容；先校验序列化、章节身份、文件名和大小上限
3. 把固定两文件意图原子保存，再分别发布完整文件
4. 支持时同步两个目标目录，删除意图，再同步意图目录
5. 任一后续受保护读取/写入先检查未完成意图：验证全部目标、内容哈希、故事项目身份、抽取与摘要的一致性，以及当前文件是旧版还是本次新版；都吻合才继续向前恢复

重复恢复不重复摘要。某个文件已经是新版时仍核对并同步目录；不会凭相同字节宣称其目录项已持久化。目标被其他写入者独立改动、意图损坏/截断/越界时停止，不覆盖冲突文件、不删除恢复证据。

这不是通用事务系统，也不覆盖正文、Canon、人物卡和全部分析文件的整批提交。当前固定意图上限 64 MiB，超限在创建意图之前拒绝；不能制造一个自身无法恢复的文件。恢复属于原来已经请求的保存操作，不代表程序替作者接受了新的小说事实。旧档案在意图建立前就存在的语义矛盾不会自动修正。

## 评测与评分不覆盖

每次 benchmark 用独占、随机后缀的运行目录；即使同秒开始，也不共用目录。用例 ID 与变体须唯一且能安全用于文件名，找不到用例时不制造“空运行”证据。

正文结果、run.json 和初始评分表都使用不覆盖发布。已有人工评分表不能被再次生成的空表覆盖；需要新表就选择新路径。失败的部分运行仍保留其已有证据，不能把不完整目录说成已完成评测。冻结 benchmark 用例及其哈希不变。

## 验证范围与尚未保证

合成测试覆盖路径越界、链接、跨平台别名、序列化失败、写入/同步/替换中断、抽取与摘要恢复、冲突意图、稳定顺序、并行启动解释器不丢摘要、同秒评测独立目录，以及已有评分保护。真实模型没有调用，真人评分没有伪造。

路径检查针对可信项目目录与配合锁协议的写入者；不声称能抵抗恶意进程在检查后调换目录的竞态。网络文件系统、硬件断电、目录创建的完整持久化、Drive、多设备写入及历史正文回滚不在本轮证明范围。临时文件可能在 SIGKILL 后残留，但不作为已保存文件读取。

相关测试：`tests/test_storage_integrity.py`、`tests/test_storage_recovery_adversarial.py`、`tests/test_boltons_atomic_port.py`、既有原子 JSON/摘要/工作台/benchmark 测试。CI 对 Linux Python 3.11 与 3.12 运行完整核心测试；可选依赖的跳过应单独报告，不代表运行了全部上游仓库。
