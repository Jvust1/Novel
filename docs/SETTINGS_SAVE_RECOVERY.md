# 故事设定与总纲的固定保存和中断恢复

本轮在 #70 的故事设定来源保护上，补上两个已复现缺口：另一会话只改平面总纲时，旧保存仍可能覆盖新内容；进程在故事设定写成后退出，新会话可能读到新设定与旧总纲。本轮使用原有项目锁、boltons 单文件原子发布，以及 Style Lab / 记忆提交已有的固定内容与回执模式，只处理 `memory/story_bible.json` 和 `memory/outline.json`。

主入口仍是 GPT + GitHub 插件读取规则与作者指定的私有故事档案。下面描述可选本地工作台的真实文件行为，不要求普通 GPT 用户安装或执行程序，不把恢复文件当作作者接受。

## 工作台操作

加载项目时，在同一项目锁内读取完整两份文件与各自原始字节指纹。只存在其中一份的旧项目仍可读取；缺失文件、空对象、空总纲分别保留身份。已有作者扩展字段会随保存保留，损坏内容先停止核对，不猜补或覆盖。

点击“保存故事设定到本地”时，冻结当时两份完整新内容、两个已加载的原文件版本和本次请求标识。任一来源变了，停止保存并保留编辑。重排 JSON 或只改作者扩展字段也会使原始字节版本失效。

保存中断或读回失败后：

1. 当前编辑、旧基线和同一份原保存请求保留。可以下载当前故事设定与总纲草案，文件也包含完整总纲对象中的扩展字段
2. 写作、人物、大纲及其他后续资料操作暂时停止，避免在同值 Bible 或半保存时继续。点击“重试这次故事设定保存”只重试原操作，不重新调用模型
3. 若已经编辑了新输入，不能把它伪装成旧请求重试。先保留新草案，在新会话读取原保存的恢复结果并核对，再决定怎样整理新编辑
4. 重新启动后，普通 ProjectStore 读取会先恢复唯一合法的待保存操作，或者因冲突停止。不会把半套资料作为已完整载入，也不会根据旧回执覆盖之后保存的新版本

只有两份当前文件都真实读回，且与原请求结果一致，才更新界面保存基线。原操作已完成但当前文件又变了，回执只证明历史成功；旧界面仍须重新读取核对，不能悄悄换基线后覆盖新稿。

保存了不同的设定或平面总纲后，旧场景计划不能直接继续写正文。明确重新生成计划，或重新载入所选层级大纲章节并核对后再继续。原来的每次 HTTP 请求前后与最终发布检查也绑定两份实际保存来源。未保存的编辑仍是作者草案，本轮不新增统一接受状态。

## 固定保存边界

写入数据之前，先以不可覆盖方式发布并读回 `.settings-commit-transaction.json`。它保留完整旧内容、新内容、项目根目录、本次请求身份以及两份文件的指纹。恢复前先核对两份文件：每份都必须等于原值或本次目标值，任一第三版本出现，就保留意图与文件并停止。

恢复只向前完成这两个固定的新内容，每份写后读回，最后写入不可覆盖的 `memory/settings_commits/` 回执，再清理意图。异常可能发生在写入前、部分写成、全部写成或回执完成后的清理阶段，不能据此声称回滚。相同请求的精确重试不会重复增量或重放旧内容；复用同一标识提交不同内容或基线会拒绝。

新的设定意图与风格、记忆、旧摘要提取意图互斥。普通读取在恢复任何一份前检查并存冲突；直接提交入口与记忆来源捕获也有相应检查。来源变化会使旧记忆候选失效，不自动重新确认或计算一份“已接受”记忆。

两份文件各自仍由原单文件原子写入发布。所有合作读取者使用 ProjectStore 时先完成或拒绝未决操作；直接绕过它读取原始文件的人仍可能看到中间状态。这不是跨设备锁、Drive 事务、恶意目录竞态沙箱或硬件断电证明。文件和完整恢复记录都有既定 64 MiB 限制，不承诺无限大小。

## 执行器接口与验证

`settings_commit.load_settings_bundle` 实际读取两份来源，`prepare_settings_save` 准备保留扩展字段的完整内容，`commit_settings_bundle` 使用显式的 `files`、`expected_before` 与固定 `request_id`。`author_workflow.save_workbench_story_settings` 现在是同一固定提交入口的适配器，也要求这三个参数。旧的 Bible-only 位置参数无法证明总纲来源，不能再借保存时的新读取猜造旧基线。

验证覆盖原创离线 AppTest、完整原始字节 CAS、未知字段、错误恢复记录、每个发布/读回/目录同步点故障、真实子进程退出、双进程竞争、原请求重试与历史回执、项目切换及记忆确认失效。进程退出测试不等于物理断电测试；HTTPX MockTransport 不等于真实模型或文学质量验收。

原依赖、许可、预算、记忆确认、接受历史、人物/层级大纲/风格绑定、参考解码与 PDF 修复继续保留。精确通过与未运行范围以[候选记录](../governance/settings_save_candidate.json)、对应 Draft PR 的实际提交 CI 和交付解包验证回执为准。外部 AI 对公开摘要的前后咨询不等于阅读源码或执行测试。
