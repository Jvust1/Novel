## 可选的本地程序入口

运行 `python -m streamlit run app.py`。Python 3.11/3.12，依赖使用 `python -m pip install -r requirements-dev.txt`。仅生成计划/正文、模型审校与记忆抽取需要配置模型；大纲导入、人工评分和 ZIP 打包本地完成。

1. 在“故事与大纲”展开层级大纲。粘贴 Markdown：`#` 全书、`##` 卷、`###` 情节线、`####` 章、`#####` 场景。不能跳级。代码围栏里的标题保留为备注；不是完整 CommonMark 文档导入器。
2. 解析只是预览。检查可编辑 JSON 并保存，再选择章节、确认本地保存编号（例如 001），点击载入写作工作台。
3. Markdown 不臆造人物选择、阻力、代价、状态变化。先生成完整场景计划，或在 JSON 中补齐这些字段；来自大纲的空计划不能直接写正文。
4. 大纲的祖先/本章上下文进入计划、正文和审校；不会把其他章节全文塞进上下文。大纲保存变化或章节编号变化时，旧绑定会拒绝继续使用。切换到新章可清空待写计划，再载入/生成。
5. 保存正文同时记录其计划和正文 SHA。已有正文默认拒绝覆盖；换章或重新载入时，覆盖勾选自动清除。生成结果的章节编号和磁盘正文版本都匹配，才允许记忆抽取。
6. 在“市场审阅与发布”按真实阅读顺序填写恰好 3 或 20 个已保存 ID，填写题材、目标读者、书名、看点和简介。系统不按文件名字母顺序推断章序，也不能证明任意选出的章节就是作品实际开篇。
7. 下载空白 CSV，人工填写同一 reviewer_id、十项整数评分及备注后粘贴。缺项、重复项、错项目、换稿、改变题材/读者都会拒绝使用旧评分。没有评分仍可生成明确标记“待人工审阅”的候选包。
8. 候选 ZIP 包含正文、大纲上下文（若有）、发布元数据、原章节 ID/正文摘要清单和空白评分表；已填写的分数与汇总独立存为 JSON。下载与保存都是本地操作，不提交到平台。

## 保存与恢复

- `memory/hierarchical_outline.json`：已保存大纲
- `memory/release_workspace.json`：点击保存的发布资料及评分文本
- `memory/chapter_plans/`：与磁盘稿件摘要绑定的计划记录，不保存正文
- `chapters/`：正文
- `exports/release-<sha256>.zip`：内容寻址候选包；重复保存同一包复用，不覆盖历史包
- 同一会话换书可恢复未保存编辑；重启只能恢复已保存资料。模型凭据不进入这些文件
- 单个 JSON 替换和候选包保存有原子写入保护；正文与计划仍是两个独立文件，不宣称跨文件事务。若计划记录失败，正文可能已经保存；界面保留之前的正确结果绑定，需核对稿件再继续

## 兼容性与评测身份

`MarketCorpus.fingerprint()` 使用 `market-corpus-v2`，涵盖项目、阶段、目标读者、题材、审阅备注与有序标题/正文。旧版仅绑定正文的 CSV 不自动迁移，必须重新生成并人工复核。不能通过重贴旧分数来声称对新背景完成审阅。

层级位置 ID 对完全相同输入稳定；插入、改名或重排 Markdown 标题可能改变 ID。正文存储编号由作者显式确认，与位置 ID 分开。可编辑 JSON 不等于已确认的写作计划。
