# GPT + GitHub 插件实写演示

这是一章专门为插件读写验证新创作的公开测试小说，不是用户的私有原稿。真实作品、私人设定与记忆仍默认保存在私有 Drive；本示例不授权自动公开未来作品。

## 本次实际链路

1. 使用 GitHub 插件读取 Novel 写作规则与对话协议的固定版本
2. 由当前 GPT 创作场景计划与完整候选章节，保留审校与连续性记录
3. 在当前可用的 Python 执行环境中调用现有 Novel 数据模型与离线诊断；GitHub 插件本身没有执行 Python
4. 使用 GitHub 插件将文件保存到隔离测试分支，并用插件重新读取核对正文和状态

## 下次对话的读取顺序

1. 本 README 与 `sources.json`：确认分支、规则版本和演示范围
2. `story_state.json`：恢复故事 ID、基础版本、当前阶段和接受状态
3. `scene_plan.json`、`chapter_plan.json`：读取场景意图；它们是待作者审阅的候选计划
4. `chapter-001.md`：必须读取完整正文，不能仅凭摘要声称恢复修订现场
5. `review.json` 与 `diagnostics.json`：区分 AI 编辑观察、离线启发式检查与未运行项目
6. 先向作者说明当前是待审阅候选 r1，再按明确指令修改或接受；不自动写下一章、不擅自将候选观察并入正式记忆

所有接受字段保持 null/false。一次要求试写，不等于作者已经认可计划、正文、设定或记忆更新。若作者接受具体版本，后续才生成正式记忆更新候选，并经确认保存新 revision。

## 能证明什么

本测试证明当前会话可以通过插件读取仓库规则、写入完整原创测试章与恢复材料，并重新读回核对。文件读取不等于自动运行仓库代码；没有执行环境时，GPT应只按文本协议工作，不得声称已跑程序、得出哈希或通过测试。

不能证明作品适合发布、已通过独立真人盲评、不存在与全部外部作品的相似性，或之后的 GPT 会自动遵守所有规则。没有调用付费模型 API，没有部署新服务，没有修改或合并 main。
